# BAA Definition of Done

For every module:
- [x] Scope matched to the roadmap.
- [x] No fabricated external data or claims.
- [x] External input validation exists.
- [x] Backend/server validation is added where a server boundary exists.
- [x] Security-sensitive behavior is explicit and defensive.
- [x] Honest limitations are documented.
- [x] Module-specific test exists.
- [x] Batch/focused test exists.
- [x] Existing regression suites are re-run.
- [x] README/status documentation is updated.
- [x] Files changed are recorded.

Continuous build result: M32–M62 implemented; final available regression 45/45 PASS.

## UI Reachability Gate — Finalized
A Blueprint module is not COMPLETE merely because its JavaScript file exists, loads, is unit-tested, or appears in Feature Explorer. COMPLETE requires: (1) a real visible host-page control, (2) a real call to the module API using page/user input, (3) the result rendered back into the UI, (4) honest insufficient-evidence/error handling, and (5) regression coverage for the UI wiring.

## Status-document accuracy rule

Status and gap-register documents must be regenerated by reading the current source code, UI, database schema/migrations, tests, and deployment configuration. They must never be carried forward from memory, assumptions, or historical completion claims.
