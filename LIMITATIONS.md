# BAA Current Limitations

This file is the project-wide honesty register.

- The current baseline remains substantially browser/localStorage-oriented.
- Server authentication/authorization and production database enforcement are not equivalent to local UI controls.
- External services are not considered connected until credentials/endpoints and successful integration tests exist.
- Scholarship, job, competition and curriculum facts are not invented when live/verified source data is absent.
- Human-review modules create auditable workflows but cannot manufacture a human decision.
- Voice depends on browser speech capabilities.
- Virtual labs are safe deterministic simulations; they are not physical laboratories.
- Multilingual responses do not constitute professional translation certification.
- Wellbeing/cognitive-safety features are non-diagnostic and do not provide medical care.
- AI explainability describes recorded evidence and product rules; it does not expose proprietary model internals.
- M61 defines a controlled testing framework; it does not claim a one-year longitudinal study has occurred.
- M62 defines a council-review record; it does not claim that external AI models or experts were consulted unless their actual responses are stored.

## Mastery Gate / Forecast limitations

- Progression currently follows the server-known assessment catalog order; a curriculum-specific progression graph is still preferable for a large production curriculum.
- Parent bypass is an exception mechanism and does not erase findings.
- Forecasts are bounded evidence-based estimates; they are not guaranteed exam marks.
- Real deployment verification requires the production PostgreSQL environment and authenticated parent/student accounts.
